# On-device model survey — 2026-09-02

Scope: candidates to replace or augment BlazeFace (face detect), MoveNet MultiPose
(person detect), HSE-FaceRes (gender/age/descriptor), and nsfwjs, inside a Web
Worker running in Android WebView / WebView2, TF.js + WebGL today. Every claim
below carries a source URL. "UNVERIFIED" means a search/fetch did not surface a
number or a license text this session — treat as unconfirmed, not as false.

**Licence rule applied throughout:** MIT / Apache-2.0 / BSD-3-Clause only pass.
GPL/AGPL and "non-commercial research only" are DISQUALIFIED and marked as such
even when the code repo itself is permissive — several projects here split code
and weights under different terms, and the weights are what we'd actually ship.

**Standing caveat:** almost every accuracy/speed number found in the ecosystem
(WIDER FACE AP, COCO mAP, "FPS") is measured on desktop/server hardware (V100,
T4, A100, or unspecified desktop CPU) or on Qualcomm NPU-specific paths. None of
the sources below report anything on an Adreno-class mobile GPU inside a WebView.
This repo's own numbers — MoveNet costing ~500ms of a ~795ms verdict on one
device and ~3000ms of ~3900ms on an older one — are the only real mobile-WebView
data point in this whole survey. Every figure below should be read as "plausible
signal", not as a mobile prediction, until spiked on-device.

**Read:** MediaPipe's "Face Detector" is BlazeFace under a Google wrapper — not
a genuine accuracy upgrade over what we already ship, only a maintained JS
runtime. YuNet is the strongest drop-in: permissive, tiny, trained explicitly
down to ~10px faces (our regime), and its hard-AP number (0.75) is a real,
disclosed WIDER FACE score — something BlazeFace has never published. SCRFD is
the best-performing detector in the survey and is closed off entirely by its
weights licence. facex-engine's detector reports the one number in this whole
category that's measured in almost exactly our pixel range (≥32px recall).

**Read:** NanoDet-Plus-m is the standout — smaller than our current MoveNet
requant, permissive, and the only person-box candidate with a *proven* browser
build already public. MediaPipe's EfficientDet-Lite0 is the safe fallback:
larger and less accurate, but Google-maintained with an official JS runtime.
YOLOX-Nano/Tiny and the DETR family (RT-DETR, D-FINE, RTMDet) are all
Apache-2.0 and worth knowing about, but none has a demonstrated in-browser
build in this survey — they'd cost us standing up onnxruntime-web as a second
runtime. Losing MoveNet's keypoints is a real design cost: this repo's own
head-anchor, hand-coverage and person-gate logic (`docs/detection-engine.md`,
session log) currently lean on keypoints, not just a box — a box-only detector
would need that logic rebuilt around box evidence alone.

## 3. Face attributes (gender/age) at low resolution — our weakest link

| Model | Licence | Notes | Small-face data |
|---|---|---|---|
| **HSE-FaceRes (current)** | MIT | 224×224 input; our faces are 38–62px, i.e. heavily upsampled into that input — a preprocessing mismatch, not necessarily a model defect | none published at this size by anyone found |
| FairFace-trained classifier | **licence not re-verified this session — check `github.com/joojs/fairface` LICENSE before adoption** [[24]](https://github.com/joojs/fairface) | trained/evaluated with a **minimum face size of 50×50px** — closest published match to our 38–62px regime found anywhere in this survey; 97% gender accuracy overall (not broken out by size); age is **coarse buckets**, not the continuous softmax we use today [[25]](https://ar5iv.labs.arxiv.org/html/1908.04913) | closest, still not exact |
| MiVOLO / MiVOLO-v2 | Apache-2.0 per repo footer at fetch time; a Hugging Face card elsewhere states MIT — **conflicting signal, confirm exact licence before adoption**, but permissive either way [[26]](https://github.com/WildChlamydia/MiVOLO) | fuses **face + body** in one model — directly relevant since this app's subjects are frequently not facing camera; gender acc up to 99.46% (IMDB-clean, face+body), age MAE 4.24yr [[27]](https://arxiv.org/abs/2307.04616) | none at our resolution; authors explicitly say **ONNX export is not advisable** (poor batched perf) and recommend TorchScript — no browser deployment path exists today [[26]](https://github.com/WildChlamydia/MiVOLO) |
| InsightFace genderage (buffalo bundles) | **weights non-commercial only** [[6]](https://github.com/deepinsight/insightface) | — | — | **DISQUALIFIED** |
| SSR-Net / DEX successors | not re-verified this session (UNVERIFIED licence) | historically cited as MIT in its original repo; tiny (~0.32MB), 2018-era accuracy | none published at 38–62px |

**Read, and this is a finding in its own right:** the one resolution study
surfaced this session (DeepFace vs InsightFace age MAE vs. resolution,
[arXiv:2511.14689](https://arxiv.org/html/2511.14689v1)) tested down to **64px
as its lowest point** — still above our 38–62px operating band — and even that
paper doesn't give exact degradation thresholds. **Nobody in this survey has
published gender/age accuracy at the pixel sizes this app actually runs at.**
FairFace's 50px training floor is the nearest published anchor. Whichever
attribute model we pick, it needs its own on-device or synthetic-degradation
calibration pass — exactly the kind of work this repo already did for the
shipped faceres pipeline (px 38–62 measurement, GENDER_CLEAR_SCORE tuning, the
whole loop-38/39 saga in the session log). A new model does not remove that
step.

**Read:** EdgeFace-XXS is the clean win here — the smallest model in the whole
survey, a licence confirmed permissive by directly reading the file (not
inferred), and competitive LFW accuracy. It replaces only the descriptor half
of faceres, not gender/age. OSNet is the interesting orthogonal idea: it's a
**person**-appearance embedding (clothing/build, not face), which matters
because this codebase has an open, named problem with re-identifying someone
who isn't facing the camera — an appearance embedding could complement or
replace the face descriptor for exactly those coasting-track cases.

## 5. Genuinely new (2025–2026) / unified candidates

- **facex-engine** ([facex-engine/facex](https://github.com/facex-engine/facex),
  Apache-2.0) — a full stack (detection 401KB + 98pt landmarks 1.1MB + 576pt 3D
  mesh 5.6MB + MobileFaceNet-style recognition 0.8–8.4MB variants + MiniFASNet
  anti-spoof 2×1.7MB) all running **today, live, in a browser**, via
  onnxruntime-web WASM with AES-256-GCM-encrypted weights, demoed on GitHub
  Pages. Closest thing found to "one download replaces several of ours." Its
  detector's ~85% recall at ≥32px is the single most relevant accuracy number
  in this entire survey for our regime. Gap: **no gender/age head** — it would
  sit alongside, not replace, a FairFace/MiVOLO-style attribute model. Risk:
  young, single-maintainer project; the encrypted-weights design is unusual and
  worth understanding before depending on it.
- **iitolstykh/YOLO-Face-Person-Detector** — a single YOLOv8x pass detecting
  BOTH face and person classes together, which is exactly the "collapse
  BlazeFace+MoveNet into one forward pass" idea worth wanting — but it's
  **AGPL-3.0** (inherits from Ultralytics YOLOv8) [[32]](https://huggingface.co/iitolstykh/YOLO-Face-Person-Detector), so it is
  **DISQUALIFIED**. Worth recording as "the right idea, wrong licence": the
  same joint face+person fine-tune built on an Apache-2.0 base (YOLOX, NanoDet,
  D-FINE, RT-DETR) is a build-it-ourselves project, not a downloadable one.
- **D-FINE / RT-DETR** (Apache-2.0, both above) — the real 2024–2025
  architecture shift in real-time detection (DETR-family beating YOLO-family at
  comparable size). Nothing found proves either runs client-side in a browser
  today; both would need onnxruntime-web as a new runtime, and their attention
  ops are an open question on Adreno-class WebGL/WASM.
- **MiVOLO / MiVOLO-v2** (above) — the best conceptual match to our actual
  problem (gender+age from face-or-body, permissive licence) but the authors'
  own stated advice against ONNX export makes it the highest-risk pick in the
  survey for our runtime.

## Shortlist for a spike (ranked, ≤6)

1. **YuNet** (MIT/Apache-2.0) — replaces BlazeFace. Only detector in the
   permissive set with a disclosed WIDER-hard score and explicit training down
   to ~10px faces. Risk: needs onnxruntime-web or OpenCV.js; no live demo
   confirmed, so first spike is "does it even run reliably in our WebView."
2. **NanoDet-Plus-m-320** (Apache-2.0) — replaces MoveNet for box-only person
   detection. Under 2MB, has a *proven* WASM browser build already. Risk: no
   keypoints, so head-anchor/hand-coverage/person-gate logic that currently
   reads MoveNet keypoints needs a redesign around box-only evidence — this is
   the biggest non-model risk on the list.
3. **EdgeFace-XXS** (BSD-3-Clause) — replaces the descriptor half of faceres.
   Smallest model in the whole survey, licence confirmed by reading the file
   directly. Risk: unproven browser/ONNX path; still needs a separate
   gender/age model since it has no attribute head.
4. **MediaPipe Object Detector / EfficientDet-Lite0** (Apache-2.0) — the safe,
   boring alternative to #2. Official Google-maintained JS runtime, so lowest
   integration risk in the whole list, at the cost of a bigger file (4.4MB
   confirmed) and unconfirmed but likely modest accuracy.
5. **facex-engine** (Apache-2.0) — spike candidate for the "one pass replaces
   several" idea, and the only source in this survey whose face-detection
   recall figure is measured near our actual pixel regime. Risk: small/young
   project, unusual encrypted-weights design, no gender/age head so it doesn't
   fully replace faceres.
6. **FairFace-trained classifier** (licence must be re-confirmed before any
   code lands) — the only attribute model whose training regime (≥50×50px)
   approaches our 38–62px operating point. Risk: coarse age buckets instead of
   continuous, and the licence needs a direct read of the repo's LICENSE file
   before this goes anywhere near the tree.

**Explicitly ruled out:** Ultralytics YOLOv8/YOLO11 and any model built on them
(incl. iitolstykh/YOLO-Face-Person-Detector) — AGPL-3.0. SCRFD and all
InsightFace `buffalo_*`/`genderage`/model-zoo weights — non-commercial only.
RetinaFace weights carry a conflicting non-commercial signal in some sources —
verify the specific weight file's provenance before use, do not assume the
code's MIT licence covers it.

**Biggest cross-cutting risk, stated once:** almost every candidate above that
isn't already TF.js-native depends on standing up **onnxruntime-web** as a
second runtime. Its WebGL execution provider is in maintenance/deprecated mode,
WebGPU needs Chromium 121+ (unverified whether the target WebView builds meet
that), which leaves the WASM CPU backend as the realistic path — and nothing in
this survey establishes that WASM-CPU ONNX inference beats our current
WebGL-backed TF.js MoveNet on an Adreno 610. That has to be measured before any
of the above is worth adopting, not assumed from a bundle-size or param-count
table.
