Tame Scroll beyond the phone

For ZVBased on the code at release 1120 (v0.1.120)Revised after your call to become a real browser

Tame Scroll becomes a calm browser. It opens any site, while the social platforms open already cleaned. The address bar is visible by default, and Focus mode hides it for people who choose to see only their platforms.

  • What sets it apart from Brave and others: they block trackers and ads. We remove the feed, Shorts and recommendations, and add blur, on the platforms where scrolling actually happens. Platforms are cleaned bookmarks on the new tab page, so the old launcher is still the first thing you see.
  • Ads become a choice: blocked by default, with a "Show ads" switch. The pieces that block them are already separate in the code, so the switch can turn them off cleanly.
  • Order: Android first (as a browser it can also be set as the default browser), then Windows desktop 1.0, then iOS and macOS together. Tablets reuse the desktop layout.
  • The cost: a browser is expected to have tabs, history, downloads and a search engine choice. That is new work, so the ladder below adds those pieces in stages.

How the ads switch would work

Today ads are blocked in three places. All three already sit apart from the cleaning rules, so a switch can turn each of them off on its own:

  • Network blocking. blocks_request() in lib.rs, called by the Windows hook and the Android nativeShouldBlock. With ads shown, it answers "allow" for ad lists while still applying tracker lists if trackers stay blocked.
  • Pre-roll scriptlets. The engine's injected_script, including the one that prunes adSlots from YouTube's player data. With ads shown, it isn't injected.
  • The "ads" surface in the rules. rules/youtube.txt and rules/reddit.txt mark it always-on. It becomes a surface you can bring back, and always_on_ads_surface_cannot_be_shown in lib.rs changes with it, along with the "always-on" wording in CONTEXT.md.

Whether a visible ads option strengthens the legal position is for the legal thread to judge. On the product side, the default stays ads blocked, so nobody who installs it today gets a worse app.

What being a browser adds

A browser has to work with any link, so these move from "not needed" to "expected". Only the first group is needed to call it a browser honestly. The rest can follow.

Needed for 1.0

The basics

Address bar with a search engine choice, Back and Forward, tabs on desktop, a short history, and opening any link. On Android, registering as a browser so it can be the default. A phishing and malware check (such as Google Safe Browsing) is expected once people can type any address.

Later

Comfort

Downloads, bookmarks beyond the five platforms, reader view, saved passwords. Each is a feature people will ask for, but none is needed at launch.

Protection outside the five platforms

Ad and tracker blocking works on any site, because the lists are general. Cleaning rules (no feed, no Shorts) stay platform-specific. Blur outside the platforms is open: thumbnail blur could run anywhere, while live video blur is heavy enough that it probably belongs only on the platforms. That is a protection decision, so it's listed for you below.

The scaling ladder

Each step rests on the one before it, so the order matters.

  1. Android browser on Play now

    The address bar, Focus mode, opening any link, the default-browser registration and the ads switch, on top of today's app. Then the listing pack in your hands (upload key, copy, screenshots, privacy page) and the legal page. Play reviews browsers under its normal rules; the legal thread is covering the listing.

  2. Windows desktop 1.0

    Tabs, the new tab page, Focus mode with the rail, the browser-owned blur switch, in-place updates, a signed installer, and a measured desktop pass. The network ad hook already works there.

  3. iOS and macOS together

    One Apple Developer account covers both. Every iOS browser must use Apple's WebKit, which is what Tauri uses there anyway. macOS needs its own network blocking, because today's hook is Windows-only. The Core ML parity check that is waiting on a Mac happens here too.

  4. Tablets

    Android tablets and iPads in landscape get the desktop layout from step 2. No separate design.

  5. More cleaned platforms, one at a time

    Reddit and X get their measured passes before anything new is added. Each platform on each layout (mobile web and desktop web) is a rule set that a platform deploy can break, so the YouTube-change canary from your open list has to cover desktop layouts too.

What stays out

  • A browser extension. Your standing ruling, and it would split the product into two installs.
  • Our own browser engine. We use the system web view on each platform (WebView2, Android WebView, WebKit). Forking Chromium is a team-sized job.
  • Accounts, sync or telemetry. Cut in the original plan, and it keeps a solo project maintainable. If people want settings on two devices, an export file does that.
  • Our own recommendations. Building a feed would recreate what we remove.
  • Linux, for now. My suggestion: no network ad hook there either, and the audience is small. Revisit if people ask.

Decisions for you

Settled: the address bar is visible on first open and Focus mode is off until the person turns it on, because store reviewers judge the default. Onboarding can offer Focus mode as a choice.

  1. Ads switch scope.One global switch, or global plus per platform. Per platform lets people support creators on YouTube and nowhere else.
  2. Blur outside the five platforms.Thumbnail blur on every site, or only on the platforms.
  3. Default search engine.A privacy-respecting default (DuckDuckGo, Brave Search) or the user picks on first launch.
  4. Windows distribution.A signed download from the website, a Microsoft Store listing, or both.

Becoming a browser reverses two lines in docs/VISION.md and docs/plan.md ("no general-purpose browsing", ads "never user-toggleable"). They should be updated once the legal thread settles the wording, so later sessions don't argue against your decision.
