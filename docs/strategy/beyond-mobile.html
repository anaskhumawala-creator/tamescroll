Tame Scroll beyond the phone

For ZVBased on the code at release 1120 (v0.1.120)Desktop = the same Tauri app, Windows build

Grow as one calm app on every screen people scroll on, and never as a browser. The phone stays the product. The desktop becomes the place where the full protection runs comfortably, video blur included.

  • Order: Android on Play first, then a refined Windows desktop 1.0, then iOS and macOS together, with tablets getting the desktop layout for free.
  • Desktop change that matters most: one window with a rail of platforms and an app-owned top bar, instead of a separate OS window per platform. The blur switch moves into that bar so YouTube can't reset it.
  • The real limit on scale is keeping rules alive, not writing code. Desktop doubles the layouts to maintain, so the YouTube-change canary comes before any new platform.

What Tame Scroll is, next to its neighbours

Your website already has the line: the same platforms, none of the machinery. It holds up on every device because it describes what is removed, not where it runs. The three things people will compare us to each do a different job.

Privacy browsers

Brave, DuckDuckGo

Hide you from trackers while you browse anywhere. The feed, Shorts and recommendations are untouched.

Blocker extensions

uBlock Origin, Unhook

Tools you install and tune inside your own browser. Mostly absent on phones, where most scrolling happens.

Screen-time apps

Digital Wellbeing, parental controls

Limit, lock and nag. They fight the habit and feel like supervision.

Tame Scroll

one install, five platforms

Opens only the platforms you use, already cleaned: no ads, no Shorts, no algorithmic feed, optional blur. No address bar, no locks, no nags.

So the pitch on desktop is the same as on the phone. We are a front door to social media, not a way onto the web. Not having an address bar is the product, and it is also what keeps the legal story simple (that part sits with the legal thread).

Where the desktop app stands today

The desktop version is the same codebase as the phone app: the same rules, the same blur engine, the same launcher. What differs is the window model and the release plumbing. Read from app/src-tauri/src/lib.rs, WORKLIST.md and the findings docs.

Direction: one window, a rail, and controls the page can't reset

What building this means

  • One window with several pages inside. Tauri 2 can host more than one webview in a window, but only behind its unstable flag, so this starts with a short spike. If it misbehaves, the fallback is today's per-platform windows with the same rail and bar drawn in each.
  • The app bar owns the blur state. The Rust side already holds the gaze mode (set_gaze_state), so the bar writes there and each page reads it, the same way Android page loads do now.
  • Wide pages get a centred column. With YouTube's feed and sidebar hidden, the desktop page has empty space. Centring the content looks finished instead of broken.
  • In-place updates and a signed installer. Tauri's updater plugin covers the first. An unsigned Windows installer triggers SmartScreen warnings, so it needs a code-signing certificate, a Microsoft Store listing, or both.
  • A measured desktop pass, the same way YouTube earned its name on the phone. That is already item 2 on your open list.

Video blur, by device

You said live video blur on the phone is more hassle than help and you turn it off on most videos, while thumbnail blur works fine. Desktops have the headroom for it. Since this trades exposure, the defaults are your call; here is the split I'd suggest.

Phone

Thumbnails blurred, video blur opt-in

Thumbnails and feed images stay blurred. The player starts clear and has one switch to turn blur on for that video. Shorts and the algorithmic feed are already gone, so the phone stays protective without the lag.

Desktop

Smart blur on, including video

Live video blur runs by default. The app-bar switch turns it off for one video and the choice sticks through resize, fullscreen and quality changes.

Either way the "blur comes back" bug should be fixed first, because it makes video blur feel worse than it is. The video blur thread is on the phone side of this.

The scaling ladder

Each step rests on the one before it, so the order matters.

  1. Android on Play now

    The listing pack in your hands (upload key, copy, three screenshots, privacy page) plus the legal page the legal thread is writing. The AAB build already exists.

  2. Windows desktop 1.0

    The one-window shell, the app-owned blur switch, in-place updates, a signed installer, and a measured desktop pass. Most users of a desktop social app are on Windows, and the ad hook already works there.

  3. iOS and macOS together

    One Apple Developer account covers both, and both use the same WebKit engine, so the work is shared. macOS needs its own ad request blocking first, because today's hook is Windows-only. The Core ML parity check that is waiting on a Mac happens here too.

  4. Tablets

    Android tablets and iPads in landscape get the rail layout from step 2. No separate design.

  5. More platforms, one at a time

    Reddit and X get their measured passes before anything new is added. Each platform on each layout (mobile web and desktop web) is a rule set that YouTube or Meta can break with a deploy, so the canary from your open list has to cover desktop layouts as well.

What stays out

  • A browser extension. Your standing ruling, and it would split the product into two installs.
  • An address bar or general browsing. The moment we open the web, we are a privacy browser competing with Brave, and the calm is gone.
  • Accounts, sync or telemetry. Cut in the original plan, and it keeps a solo project maintainable. If people want settings on two devices, an export file does that.
  • Our own recommendations. Building a feed would recreate what we remove.
  • Linux, for now. My suggestion: there is no ad hook there either, and the audience is small. Revisit if people ask.

Decisions for you

  1. Video blur defaults per device.Phone opt-in and desktop on, as above, or one default everywhere.
  2. One-window desktop with a rail.I recommend it. The alternative is to keep separate windows and only add the app bar.
  3. Windows distribution.A signed download from the website, a Microsoft Store listing, or both. The Store listing helps with trust and updates; the direct download keeps you independent.
  4. Whether macOS waits for iOS.I recommend shipping them together since they share an account and an engine.
